# 互动剧情内容编写规范 v0.1

## 1. 单个事件的结构

一个事件必须明确：

- 它在故事中的作用：推进主线、补充人物、暴露风险、回应旧选择，或制造转折。
- 发生条件：章节、阶段、玩家身份、能力、人物关系和 flags。
- 事件文本：玩家当前看得到的事实，不泄露隐藏动机和内部数值。
- 选项：玩家能采取的行动，不写成“好/坏”或“正确/错误”。
- 规则结果：写清直接收益、代价和适用情境。
- 延迟影响：能在后续场景中被识别和追溯。
- 后续连线：明确会解锁、封锁或改变哪些事件。

## 2. 选项文案

选项描述的是行动，而不是作者的价值判断。

不合格：
- 正确处理：立即接管公司。
- 错误选择：把公司交给叔叔。

合格：
- 亲自接管企业，组建自己的管理团队。
- 暂时让叔叔继续主持经营，自己先熟悉业务。
- 聘请独立团队审计财务和经营情况。
- 先把企业事务交给现有班子，留出时间处理个人生活。

## 3. 每个选项的规则表

每个选项至少要检查：

| 检查项 | 必须写清 |
|---|---|
| 适用条件 | 什么身份、能力、关系和局势下会触发哪条规则 |
| 即时收益 | 获得了什么资源、信息、信任或机会 |
| 即时代价 | 失去什么、激化什么冲突 |
| 延迟影响 | 后续哪件事会因此出现 |
| 人物回响 | 哪些 NPC 会因关系链改变立场 |
| 反复行为风险 | 重复采取类似行动会累积什么压力 |
| 兜底 | 未命中更具体规则时如何处理 |

## 4. 随机事件

随机事件不是任意插入的“彩蛋”。

- 每个事件必须有明确 when 条件。
- 事件必须与当前人物、处境和阶段相符。
- 通过权重抽取前，先筛除不满足条件、已发生或冷却中的事件。
- 同一事件重复出现必须有明确理由；默认单局只发生一次。
- 事件选择使用游戏状态中的 PRNG，不使用 Math.random。
- 随机事件不能擅自改变主线必要事实，也不能单独决定结局。

## 5. 延迟后果

延迟事件必须记录来源选择。到期时重新检查条件，避免人物关系或局势已经改变却仍播放旧剧情。

例：
- 玩家选择亲自接管 → 一回合后叔叔重新评估你的能力与态度。
- 玩家选择独立审计 → 审计线索逐步浮现，结果取决于期间是否有人干预。
- 玩家选择暂缓处理 → 董事会对你的耐心下降，可能要求正式说明。

## 6. 文风与叙事

- 使用人物动作、对白、环境变化表达后果。
- 不直接向玩家展示系统数值。
- 不使用卦、爻、吉凶等术语。
- 不对玩家说教，不在每次选择后强行写人生箴言。
- 感悟只在阶段或最终结局出现，尽量简短且从具体经历中自然生长。

## 7. 六问验收

1. 时：同一行动在不同阶段是否会不同？
2. 位：身份、权力、能力不同是否会改变后果？
3. 应：人物之间如何相互牵动？
4. 变：这个选择改变了哪些后续条件？
5. 极：这种做法反复发生会有什么反作用？
6. 衡：收益和代价是否同时成立？
