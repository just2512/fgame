# 易经底层逻辑驱动的互动剧情引擎设计规范 v0.1

- 状态：初版实现基线
- 对应样板：《突然成为百亿富二代》
- 设计定位：易经是设计者的建模方法，不是玩家可见玩法，也不是运行时起卦算法。

## 0. 产品定义

玩家进入一个虚构的人生情境，通过一系列有代价的选择推动故事。游戏呈现人物、处境、矛盾、选择、人物反应、结果和简短感悟。

玩家界面禁止出现卦名、爻名、阴阳爻、吉凶判断、占卜结果、成功率或“命中某卦”等信息。结局只用故事语言描述，不把人生结果解释为某种卦象。

## 1. 范围与硬约束

| 项目 | v0.1 约定 |
|---|---|
| 玩家可见 | 人物、处境、矛盾、选择、剧情反馈、人生结果、感悟 |
| 玩家不可见 | 卦、爻、吉凶、易学术语、隐性数值、成功率 |
| 执行方式 | 明确、可测试的规则；运行时不“起卦” |
| 内容来源 | 人工编写的主线、随机事件、延迟事件与结局 |
| 随机性 | 带种子的伪随机数；同版本、同种子、同选择序列可复现 |
| 平台 | HTML5 + PWA，纯本地运行 |
| 存档 | IndexedDB；保存完整状态、种子和选择历史 |
| AI | 首版不依赖 AI，不在运行时生成剧情 |
| 网络 | 不需要账号、业务服务器或在线内容；首次加载/安装 PWA 仍需访问静态站点 |

## 2. 易理到设计原则的转译

这些是游戏设计约定，不宣称与传统易学术语存在一对一、唯一的学术对应关系。

| 设计借鉴 | 剧情原则 | 引擎落点 |
|---|---|---|
| 阴阳消长 | 局势由相互牵制的力量构成，力量会此消彼长 | 势线 Force：当前值、变化趋势、阶段 |
| 时 | 同一选择在不同阶段可能有不同后果 | 时间、章节、阶段条件 |
| 位 | 同一行为因身份、权力和处境不同而有不同后果 | 玩家位置 Standing、能力与选项条件 |
| 应 | 人物之间存在呼应、利益、联盟和牵连 | NPC 关系图及关系传播效果 |
| 变 | 一次选择会改变后续事件的发生条件 | Flags、势线更新、延迟后果队列 |
| 物极必反 | 某种优势持续累积到极端时，可能产生新的风险 | Pressure 累积器与条件反转事件 |
| 衡（内容约束） | 不把某种行为永久设计成占优策略 | 每个关键选项必须写明收益、代价、条件和后续影响 |

**总则：没有绝对正确的选择，只有具体处境中的取舍与代价。** 这不等于所有选择的结果必须一样好，也不等于每次选择都要随机。结果应由已知条件和明确规则解释。

## 3. 状态模型

### 3.1 Player

- Standing：身份、职务、资产、实际控制权、社会声望等位置描述。
- Skills：经营、识人、谈判、自控、胆识等能力。能力可成长，也可能因长期不使用而停滞。
- Disposition：进取、守成、重情、重利、猜疑、宽厚等隐性倾向画像。按行为累积，只用于 NPC 反应、部分选项及结局，不向玩家显示数字。

### 3.2 Forces

每条势线至少包含：

- value：有界数值，v0.1 默认限制在 0–100。
- trend：rising、stable、falling，由最近一次变化计算。
- phase：由内容定义的阶段标签，例如市场的 recovery、growth、overheated、decline、trough。

富二代样板势线：

| ID | 含义 | 初始状态 |
|---|---|---|
| company_health | 企业经营状况 | 45，下降 |
| market_cycle | 行业与市场周期 | 38，decline |
| control | 玩家实际掌控企业的程度 | 10，平稳 |
| family_tension | 家族内部张力 | 60，上升 |
| public_attention | 外界关注程度 | 30，平稳 |
| personal_liquidity | 玩家可自由支配的个人资金 | 80，平稳 |

### 3.3 NPC 与关系

NPC 包含公开目标、隐藏动机、能力、可靠度，以及玩家与其之间的 trust、debt、rivalry 等关系数据。隐藏字段不得直接写入玩家可见文案。

“应”的设计检查不只看玩家与某 NPC 的关系，也要检查此举是否会通过联盟、利益或信息传递影响其他 NPC。

### 3.4 其他状态

- time：章节、回合和经过的月份。
- flags：已发生的关键事实。
- pending：延迟后果队列。
- pressure：孤立、懈怠、人情债、曝光、过度收缩等累积器。
- trajectory：生涯轨迹标签。
- history：事件、选项、命中规则、结果及来源原因的历史记录。
- rngState：伪随机数状态；不能依赖系统时间或 Math.random 参与剧情结算。

## 4. 引擎主循环

1. 局势评估：读取势线、阶段、关系、位置、能力、标记和待处理后果。
2. 事件筛选：从人工事件库中筛选条件满足且未完成的事件。
3. 事件选择：按主线顺序处理；到达允许插入随机事件的位置时，从合格事件中按权重抽取。
4. 选项呈现：按玩家位置、能力和事实条件显示可用选项；不显示数值或正确性暗示。
5. 行为结算：按顺序匹配第一条满足条件的规则，应用明确效果。
6. 延迟排程：将未来事件写入 pending；到期时重新检查触发条件。
7. 局势演化：更新势线趋势、关系、压力、轨迹和时间。
8. 反转检查：累积器达到明确阈值时，使对应反转事件获得触发资格。
9. 终局判定：所有必需主线节点完成，或达到明确终止条件后，按优先级匹配预先编写的结局；兜底结局必须存在。

### 4.1 事件模型

事件是 JSON 数据，不是散落在界面代码中的业务逻辑。事件类型：

- main：主线关键场景，按 order 推进。
- random：满足条件后从候选池抽取，受 seed 控制。
- delayed：由此前选择排程，到期后再次检查条件。
- ending：终局匹配结果，不作为普通可选事件。

事件字段包括 id、kind、chapter、order、title、scene、when、weight、choices。选择包含 id、text、requires、resolve。resolve 是有序规则表，包含 when、outcome、narrative、effects、delayed；最后必须有无条件兜底规则。

### 4.2 条件表达式

不执行字符串表达式，不使用 eval。v0.1 使用结构化条件 AST：

- 单条件：path + op + value。
- 组合条件：all / any / not。
- 比较操作：eq、ne、gt、gte、lt、lte、in、contains。
- 路径只允许访问状态白名单内的字段；未知路径应报错，不能静默视为通过。

### 4.3 效果类型

v0.1 支持：force.delta、force.phase、skill.delta、standing.set、npc.delta、flag.set、pressure.delta、trajectory.add、schedule。效果按文件顺序应用，数值边界在引擎层统一处理。

### 4.4 结算规则

不使用单一“成功率 = 能力 × 运气”公式。按顺序匹配情境规则，首条命中规则生效。一个选项可以因能力、时机、身份、局势阶段、NPC 可靠度而出现不同的明确结果。

随机性只用于同一情境内的候选事件选择或轻微叙事差异，不允许随机数覆盖已经明确满足的规则条件。规则顺序、随机抽取和效果顺序必须确定。

## 5. 物极必反

样板累积器：

| ID | 增加来源 | 达到阈值后的可能后果 |
|---|---|---|
| isolation | 连续独断、排斥异议 | 身边无人敢说真话，重大决策缺少提醒 |
| complacency | 长期顺利、忽略风险 | 小问题被拖延并积成危机 |
| debt_of_favor | 过度依赖某个关系人 | 对方提出难以拒绝的要求 |
| exposure | 高频高调行动 | 舆论反噬、竞争者集结 |
| austerity | 长期只收缩、不行动 | 错过窗口期、影响力下降 |

必须双向设计：过度进取可能反转，过度退让也可能反转。反转事件是此前选择的后果，不是无因惩罚。

## 6. 延迟后果

每条 pending 记录包含 eventId、dueAtTurn、scheduledFrom、reason。到期时再次判断事件自身的 when；条件不再成立则按规则丢弃或转为替代事件，不得强行播放与现状矛盾的剧情。

重要选择至少应有一个可追溯的后续影响（直接、关系或延迟影响至少一项）。结局回顾应能指明关键后果源于哪次选择。

## 7. 结局生成

输入：终局势线、关键 flags、倾向画像、重要关系、轨迹标签和选择历史。

结局不做单一好坏评分，至少从成就、关系、自我、代价四个角度叙述。每个结局有必要条件、优先级和玩家可见故事文案；按优先级从高到低匹配，必须有兜底结局。

结局页只展示标题、人生叙述、简短感悟及可选的关键经历回顾。禁止展示卦象、隐性变量、数值或内部规则命中情况。

## 8. 样板：《突然成为百亿富二代》

### 8.1 初始处境

玩家原本是普通职员，突然继承家族巨额资产，但资产所有权不等于企业经营权。

| 项目 | 初始状态 |
|---|---|
| 身份 | 新继承人 |
| 经营能力 | 1 |
| 识人能力 | 2 |
| 自控能力 | 2 |
| 企业经营状况 | 45，下降 |
| 市场阶段 | 回落期 |
| 企业控制权 | 10 |
| 家族张力 | 60 |
| 外界关注 | 30 |

NPC：

- 叔叔（代理董事长）：希望保留话语权，能力较强，对继承人持观望态度。
- 陈总（财务总监）：稳健，熟悉现金流，对旧管理班子有保留。
- 老友阿杰：真诚，想创业，项目能力尚待验证。
- 赵元老：精明，关注权力格局，擅长观察风向。

### 8.2 完整版目标章节（后续里程碑）

| 章 | 主题 | 主要势线 |
|---|---|---|
| 1 | 继承与控制权 | control、family_tension |
| 2 | 第一次经营危机 | company_health、market_cycle |
| 3 | 高管与家族关系 | NPC ties |
| 4 | 机会、投资与曝光 | market_cycle、exposure |
| 5 | 朋友的创业请求 | 个人资金、关系、时机 |
| 6 | 优势累积后的反转 | pressure |
| 7–8 | 终局选择 | 全局状态 |

v0.1 只实现第一章垂直切片，至少覆盖控制权选择、现金流问题、朋友请求、随机/延迟事件及多个阶段性结局。不得把此切片描述为完整 8–10 章故事。

### 8.3 第一章选择约束

| 选择方向 | 潜在收益 | 代价 / 风险 |
|---|---|---|
| 亲自接管 | 提高控制权、建立新班底 | 缺乏经验时暴露能力短板，触发旧班子防御 |
| 暂时信任叔叔 | 获得经营缓冲，降低短期冲突 | 权力可能被继续稀释，形成依赖 |
| 聘请专业团队审计 | 获得信息，发现经营事实 | 触怒旧班子，问题暴露后必须承担处理责任 |
| 暂时享受新生活 | 获得个人空间、观察外界、结识关系 | 错过处理窗口，企业问题可能恶化 |

“先享受生活”不是错误选项。它可能导向与经营权无关的个人生活路径，也可能因错失窗口而被迫回到企业危机。

## 9. 内容编写规范

每个事件必须完成六问检查：

1. 时：同样选择在不同阶段是否可能产生不同结果？
2. 位：身份、权力或能力不同是否改变后果或选项？
3. 应：会牵动哪些人物，影响如何传播？
4. 变：会改变哪些后续事件条件？
5. 极：若重复这一行为，累积风险是什么？
6. 衡：每个选项是否写清收益、代价、条件和延迟影响？

文风：不用易学术语或宿命论口吻；不写“你选择了正确的路”；通过人物反应、行动结果和环境变化传达后果。叙事避免把状态数值直接翻译成“你的人品+10”。

## 10. 测试与验收

- Schema：所有事件 ID 唯一，引用的事件、NPC、势线、技能、标记必须存在。
- 确定性：同一版本、seed 和选择序列逐字复现。
- 可达性：每个结局至少存在一条可达路径。
- 死局：任何可达非终局状态都必须有下一事件或明确终止结果。
- 规则覆盖：每个选择至少有一条可匹配规则和兜底规则。
- 时位：关键选项至少在两种情境下得到不同的、可解释的结果。
- 延迟：排程、到期、条件复核和来源追踪均有测试。
- 策略检查：激进、保守、重关系、重利益等测试策略不能因规则漏洞而稳定垄断所有有意义的结局。
- UI 边界：生产界面不出现内部卦爻、状态数值、概率或调试信息。
- 离线：首次加载后重新打开应用，无网络时可载入已缓存界面和本地存档。

## 11. 技术实现

- TypeScript + Vite。
- 内容：JSON；类型定义与运行时校验分离。
- 模块：state、conditions、resolver、scheduler、pressure、ending、storage。
- UI：只负责叙事展示和输入，不承担剧情规则。
- 存档：IndexedDB 保存完整状态、seed、选择历史和内容版本。
- RNG：显式 PRNG 状态；不得让 UI、时间戳或外部网络参与剧情随机性。
- 开发调试信息只在开发环境输出；正式界面不显示。

## 13. v0.1 未决事项

- 单局目标时长：先以 10–15 分钟的第一章垂直切片验证阅读节奏，完整剧本再根据试玩调整。
- 文风：现代都市、轻松克制，不做说教。
- 重玩：保留不同选择形成的不同人生路径，不显示攻略式“最佳路线”。
- 成长：玩家不看能力数值，通过选项、人物态度与事件反应感知成长。
